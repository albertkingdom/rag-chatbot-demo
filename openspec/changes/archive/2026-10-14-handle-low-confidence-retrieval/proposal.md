## Problem

檢索品質不足（重排後 top-1 分數低於門檻 0.3）時，系統仍會照常生成答案，帶來下列問題：

1. prompt 允許在 context 不相關或為空時改用一般知識回答，模型可能杜撰 CarbonM 系統不存在的操作步驟或畫面名稱，使用者難以分辨（風險推論，尚未實測）。
2. 低分時送出的「來源」仍是那批不相關的 Q&A，讓這類答案看起來有依據。
3. 低分的答案照樣寫入語意快取，24 小時內相似問題（相似度大於 0.95）可能命中；手冊同步流程不會清除快取，期間即使補上手冊也不會重新檢索。（目前快取只比對任意 5 筆，因此命中並不保證，但快取範圍擴大後會變得穩定。）
4. 重試檢索的結果無條件覆蓋第一次結果，即使重試的分數更差；改寫查詢出錯時會回傳原查詢，等於用相同查詢白跑一次檢索。
5. 評分結果與重試次數只留在日誌與 LangSmith 追蹤，沒有寫入對話紀錄，無法在資料庫端彙總統計低分比例，也不便依資料調整門檻（日誌與追蹤雖有分數，但難以彙總）。

「低分時可用一般知識回答」本身是文件明載的刻意取捨（為了讓被關鍵字誤路由的一般問題仍可回答），本次不推翻；本次處理的是它帶來的標示、來源、快取與紀錄缺口。

## Root Cause

聊天服務層在重試迴圈結束後不再讀取評分結果；快取寫入與來源輸出的條件都只看「有沒有答案」；重試結果以賦值直接覆蓋；對話紀錄寫入時沒有帶檢索相關欄位。

## Proposed Solution

- 重試時保留 top-1 分數較高的檢索結果；分數相同保留較早的結果。
- 改寫後的查詢與任何已試過的查詢相同（含改寫失敗回傳原查詢、回傳空字串）時，停止重試，不再檢索。
- 最終保留的檢索結果仍未通過評分（含完全沒有檢索結果）時，視為低信心：
  - 由伺服器在答案開頭固定加上一句說明（文字見 design），表明知識庫查無直接相關資料、以下為一般性參考說明，使標示不依賴模型是否遵守。
  - 生成 prompt 加入低信心說明，要求模型只在資料明確寫出答案時才引用、否則僅以一般知識簡答，不得杜撰 CarbonM 的具體操作步驟、畫面或選單名稱，且不必重複說明查無資料。
  - 不送出來源事件；不寫入語意快取；對話歷史與紀錄照常寫入（內容含上述固定說明）。
- rag 路徑寫入對話紀錄時，在 metadata 加入檢索信心欄位（保留結果的 top-1 分數、每次檢索的分數、重試次數、保留的是第幾次、是否低信心、評分門檻、是否因改寫查詢重複或為空而提早結束重試）。
- 生成 prompt 新增的變數有預設空值，既有呼叫端（直接回答路徑與評估腳本）不需修改。

## Non-Goals

- 不改評分門檻 0.3、重試上限預設值與評分方式（仍以重排 top-1 分數判斷，不新增 LLM 評分）。
- 不改為「低信心時直接拒答」；採標示後仍回答，替代方案留在 design 的待決問題。
- 不新增串流事件型別或欄位，前端與事件格式不變；不在介面上顯示低信心標記。固定說明是答案文字的一部分。
- 不處理語意快取的查詢涵蓋範圍（由 fix-cache-lookup-coverage 處理）；不在手冊同步後清除快取。
- 不在組 prompt 時去除對話歷史中的固定說明：歷史存全文，使重新整理頁面後仍看得到標示；是否需要去除列為待決問題。
- 不調整評估腳本與評估題庫：評估腳本直接呼叫檢索鏈與生成鏈、繞過評分與重試，因此無法量測本變更的效果，需另案處理。

## Success Criteria

- 重試分數低於第一次時，生成使用第一次的檢索結果；重試分數較高時使用重試結果；分數相同時使用較早的結果。
- 改寫查詢與任何已試過的查詢相同或為空時，不發生額外檢索，重試次數紀錄為實際多做的檢索次數。
- 低信心時：答案以固定說明開頭；生成輸入帶有非空的低信心說明；回應不含來源事件；語意快取沒有新增條目；對話歷史與紀錄含這一輪；輸出防護攔截時沿用既有的防護行為（不寫歷史與快取）。
- 高信心時行為與現在相同：來源照送、快取照寫、生成輸入的低信心說明為空字串、答案沒有固定說明。
- 固定說明本身不會觸發既有的輸入輸出防護規則（由測試確認）。
- rag 路徑的對話紀錄含檢索信心欄位。
- 既有呼叫生成鏈但不提供低信心說明的程式（評估腳本、直接回答路徑）不需修改即可執行。
- 架構文件、README 功能條目與流程圖已同步更新。

## Impact

- Affected specs: low-confidence-handling（新增）。既有的 web-frontend 規格寫明「有來源時才送出來源事件」，低信心時系統視為沒有來源，行為相符，不需修改；stream-response 與 cache-key-stability 的需求不變。
- Affected code:
  - Modified: src/chat_service.py, src/retrieval_grader.py, src/rag_pipeline.py, tests/test_chat_service.py, tests/test_retrieval_grader.py, architecture.md, README.md
  - New: tests/test_rag_prompt.py
  - Removed: (none)
- 相關但不修改：scripts/real_rag_smoke.py 會斷言回答含來源，知識庫內問題若因低信心而沒有來源，該腳本會失敗；這是預期的回歸訊號，不需調整。
- 合併順序：建議先於 fix-cache-lookup-coverage 合併或同版部署，避免快取查詢範圍擴大後，低品質答案被穩定命中。
